# NOVA Messenger — обязательные правила разработки

## 1. Гостевые аккаунты
- Гость получает уникальный ник `nova1`, `nova2`, `nova3` и т. д.
- Гость может искать пользователей, отправлять/принимать заявки в друзья, писать личные текстовые сообщения и совершать аудиозвонки.
- Гость не может создавать группы, отправлять подарки, загружать медиа или использовать Premium-функции.
- Не блокировать отправку текста и аудиозвонки только потому, что `auth.currentUser.isAnonymous === true`.
- При регистрации из гостевого профиля использовать привязку учётных данных к текущему anonymous-пользователю, чтобы сохранить UID, ник, друзей и историю чатов.

## 2. Firebase и безопасность
- Не публиковать открытые правила вида `.read: true` или `.write: true`.
- Для сообщений разрешать чтение/запись только участникам соответствующего чата; при записи проверять `senderUid === auth.uid`.
- Для звонков разрешать сигналинг только участникам звонка.
- Не доверять ограничениям только в интерфейсе: защищать данные правилами Realtime Database.
- После изменения `docs/firebase-database-rules.json` обязательно опубликовать правила в Firebase Console → Realtime Database → Rules. Коммит в GitHub сам по себе правила Firebase не применяет.
- В Firebase Authentication должны быть включены используемые методы входа: Email/Password и Anonymous (для гостевого входа).

## 3. Android APK — критерии готовности
Перед объявлением APK рабочим проверить установленную сборку на настоящем Android-устройстве:
1. Регистрация email/пароль и повторный вход.
2. Гостевой вход с выдачей уникального ника.
3. Поиск пользователя, заявка в друзья, принятие заявки и создание личного чата.
4. Отправка и получение текста между двумя аккаунтами.
5. Входящий и исходящий аудиозвонок между двумя устройствами.
6. Запрос разрешений Android на микрофон и камеру перед звонком/видеозвонком.
7. Сохранение входа после закрытия и повторного запуска приложения.
8. При ошибке показывать понятный текст и записывать исходный код ошибки в Android WebView console/logcat.

## 4. Правила исправлений
- Не считать сборку успешной только потому, что APK создан: проверять логи GitHub Actions и поведение на устройстве.
- Не удалять рабочие функции ПК при исправлении Android.
- После изменения Firebase/Auth/calls проверять одновременно Windows и Android.
- Исправлять первопричину; не скрывать ошибки и не обходить безопасность базы.
